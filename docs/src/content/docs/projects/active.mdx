## [🛥️ KSail](https://github.com/devantler-tech/ksail) ![Go](https://img.shields.io/badge/Go-00ADD8.svg?style=for-the-badge&logo=Go&logoColor=white) ![Docker](https://img.shields.io/badge/Docker-2496ED.svg?style=for-the-badge&logo=Docker&logoColor=white) ![Kubernetes](https://img.shields.io/badge/Kubernetes-326CE5.svg?style=for-the-badge&logo=Kubernetes&logoColor=white)

## [☸️ Platform](https://github.com/devantler-tech/platform) ![Kubernetes](https://img.shields.io/badge/Kubernetes-326CE5.svg?style=for-the-badge&logo=Kubernetes&logoColor=white) ![Flux](https://img.shields.io/badge/Flux-5468FF.svg?style=for-the-badge&logo=Flux&logoColor=white) ![Talos Linux](https://img.shields.io/badge/Talos-FF7300.svg?style=for-the-badge&logo=Talos&logoColor=white)

<Image src={platformImg} alt="Illustration of connected local and cloud infrastructure" />

A [Flux](https://fluxcd.io/) GitOps-based Kubernetes cluster running on [Hetzner Cloud](https://www.hetzner.com/cloud/). It demonstrates a production-grade approach to working with Kubernetes using [Talos Linux](https://www.talos.dev/) — provisioned via [KSail's native Hetzner provider](https://github.com/devantler-tech/ksail).

The platform supports software development and self-hosted applications. It is also a place to explore cloud-native technologies; its experimental and personal workloads should not be read as a promise about a customer’s hosting agreement.

**Key Technologies**: [Cilium](https://cilium.io/) (CNI & [Gateway API](https://gateway-api.sigs.k8s.io/) ingress), [cert-manager](https://cert-manager.io/) (TLS), [SOPS](https://getsops.io) & [External Secrets](https://external-secrets.io/) + [OpenBao](https://openbao.org/) (Secrets), [external-dns](https://kubernetes-sigs.github.io/external-dns/) with [Cloudflare](https://www.cloudflare.com) (DNS)

## [⬡ Data Product Controller](https://github.com/devantler-tech/data-product-controller) ![Go](https://img.shields.io/badge/Go-00ADD8.svg?style=for-the-badge&logo=Go&logoColor=white) ![Kubernetes](https://img.shields.io/badge/Kubernetes-326CE5.svg?style=for-the-badge&logo=Kubernetes&logoColor=white)

A cloud-native controller and open contract for building **composable data products**. A Kubernetes `DataProduct` resource describes ownership, dependencies, data interfaces, and an independently hosted UI; the controller publishes ready products through a central registry without coupling that registry to any product implementation. The same descriptor can therefore be consumed by other compatible portals, and products can depend on products to form larger aggregates and data spaces.

The initial v1.0 foundation includes the CRD and reconciler, registry API and UI, standard query and OpenAPI surfaces, and a standalone Harbour demonstration product. Source provisioners, connection integrators, and aggregate execution remain explicit roadmap work rather than capabilities claimed by this first release.

🗺️ [Roadmap](https://github.com/devantler-tech/data-product-controller/issues/1) · 🔎 [Explore the hosted registry](https://data-products.platform.devantler.tech)

## [⚔️ World at Ruin](https://github.com/devantler-tech/world-at-ruin) ![Godot Engine](https://img.shields.io/badge/Godot-478CBF.svg?style=for-the-badge&logo=godotengine&logoColor=white) ![Kubernetes](https://img.shields.io/badge/Kubernetes-326CE5.svg?style=for-the-badge&logo=Kubernetes&logoColor=white)

A **source-available, cloud-native MMORPG built almost entirely by AI agents** — the newest and most experimental project in the portfolio. Everything is authored as code and built headlessly in CI: a [Godot 4](https://godotengine.org/) client with procedurally generated worlds, and an [Agones](https://agones.dev/)-based server tier planned on the Platform above. Progress is meant to be watched by *playing* — every player-visible change lands in the in-game dev log.

Currently in **pre-alpha**, and playable now on macOS — [install it with Homebrew, or download the app directly](https://github.com/devantler-tech/world-at-ruin#play-it). You wake in a cave, shape your character, and walk out into the ruins; combat and networking come later. The full settled design lives in the repo's [AGENTS.md](https://github.com/devantler-tech/world-at-ruin/blob/main/AGENTS.md).

🎮 [Install & play](https://github.com/devantler-tech/world-at-ruin#play-it)

## [⚡ Actions](https://github.com/devantler-tech/actions) ![GitHub Actions](https://img.shields.io/badge/GitHub%20Actions-2088FF.svg?style=for-the-badge&logo=GitHub-Actions&logoColor=white)

A collection of [composite GitHub Actions](https://docs.github.com/en/actions/tutorials/create-actions/create-a-composite-action) that provide small, reusable components for CI/CD workflows.

- **Aggregate Job Checks**: Aggregate multiple job results into a single required check
- **Approve PR**: Approve a PR using a GitHub App identity
- **Dependency Review**: Scan a PR's dependency changes for vulnerabilities and disallowed licenses
- **Diagnose Flux**: Dump [Flux](https://fluxcd.io/) reconcile state, controller logs, and failing pod logs to debug a stuck deploy in CI/CD
- **Enable Auto-Merge**: Enable auto-merge on a pull request
- **Cleanup GHCR**: Clean up old [GitHub Container Registry](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry) packages
- **Free Disk Space**: Reclaim runner disk space by removing large preinstalled toolchains
- **Guard Installed Skill Edits**: Refuse a hand-edit to a synced installed-skill tree, naming the upstream that owns it
- **Login to GHCR**: Authenticate with the GitHub Container Registry
- **.NET Test**: Test [.NET](https://dotnet.microsoft.com/) solutions or projects
- **Setup Agent Skills**: Install agent skills via `gh skill` for one or more agents (e.g. GitHub Copilot, Claude Code)
- **Setup Go Toolchain**: Set up Go with optional private module support
- **Setup KSail**: Install [KSail](https://github.com/devantler-tech/ksail) CLI via [Homebrew](https://brew.sh/)
- **TODOs**: Create GitHub issues from TODO comments in code
- **Update Agent Skills**: Run `gh skill update --all` and report changes
- **Upload Coverage**: Upload a Cobertura XML coverage report to GitHub Code Quality
- **Upsert Issue**: Create, update, reopen, or close a GitHub issue by title
- **Validate Manifest Naming**: Check that Kubernetes manifests and machine patches follow a configurable naming convention
- **Validate Retired Repository Links**: Reject links to retired GitHub repositories, with documented historical exceptions
- **Validate Shell Pipelines**: Find early-exit `grep` assertions in shell scripts before `pipefail` can invert their result

## [🛜 UniFi Provider](https://github.com/devantler-tech/provider-upjet-unifi) ![Crossplane](https://img.shields.io/badge/Crossplane-1A1A1A.svg?style=for-the-badge&logo=crossplane&logoColor=white) ![Kubernetes](https://img.shields.io/badge/Kubernetes-326CE5.svg?style=for-the-badge&logo=Kubernetes&logoColor=white) ![Go](https://img.shields.io/badge/Go-00ADD8.svg?style=for-the-badge&logo=Go&logoColor=white)

A [Crossplane](https://crossplane.io/) provider for [Ubiquiti UniFi](https://www.ui.com/), generated with [Upjet](https://github.com/crossplane/upjet) from the [`ubiquiti-community/terraform-provider-unifi`](https://github.com/ubiquiti-community/terraform-provider-unifi) Terraform provider. It turns UniFi networks, WLANs, firewall rules, VPN/WireGuard, devices and settings into Kubernetes custom resources, so network configuration lives in Git and is reconciled like everything else — the same way the [Platform](https://github.com/devantler-tech/platform) cluster consumes the upstream GitHub provider.

## [🛡️ Kyverno Policies](https://github.com/devantler-tech/kyverno-policies) ![Kyverno](https://img.shields.io/badge/Kyverno-1D9BF0.svg?style=for-the-badge&logo=kyverno&logoColor=white) ![Kubernetes](https://img.shields.io/badge/Kubernetes-326CE5.svg?style=for-the-badge&logo=Kubernetes&logoColor=white)

A shared catalog of [Kyverno](https://kyverno.io/) policies — the rules that decide what may run on a cluster and fill in what a workload left out. Writing them once here means the [Platform](https://github.com/devantler-tech/platform) and the [Platform Template](https://github.com/devantler-tech/platform-template) inherit the same guardrails instead of each keeping a copy that quietly drifts. Every policy ships with a Kyverno CLI test pinning the behaviour it promises, so a change that would loosen a guardrail fails before it reaches a cluster.
